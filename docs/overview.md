# Audio retrofyer — サービス全体像

> サービスの設計イメージ（UX・画面・内部データフロー）をまとめたもの。
> 作業ルール／スタックは [`../CLAUDE.md`](../CLAUDE.md) を参照。

## 1. 一言でいうと

**「音源を放り込む → 採譜される → 音色を選んで鳴らし直す / 眺める / 書き出す」を 1 画面で完結させる、遊び用のリミックス箱。**

- サーバなしの静的 SPA（完全クライアント完結）。
- 原曲への忠実さではなく「**別音色化の面白さ**」が主役。採譜の粗は味になる。
- 相性が良い素材: 音数が少なく音が立っているもの（lo-fi / アンビエント / ループ / シンプルなピアノ・シンセ）。

## 2. ユーザー体験の流れ（状態遷移）

```
①入力待ち ──ファイルD&D / タブ音声キャプチャ──▶ ②デコード中
                                                      │
                                                      ▼
④結果ビュー ◀──採譜（重い・進捗バー）── ③採譜中
   │  ・ピアノロール表示
   │  ・音色ドロップダウンで鳴らし直し（再生/停止/シーク）
   │  ・MIDI / sf2 音色を切り替え
   └──▶ ⑤書き出し（.mid ダウンロード）／ もう一度別の曲へ
```

**体験の肝**: ③採譜は重い。「固まった?」と思わせないこと（進捗バー＋Web Worker）。

│  ─── 採譜後 ───────────────────────────────  │
│  ▶ ⏸  ━━━━●────────  0:12 / 1:30            │  ← 再生バー
│  音色: [ オルゴール ▾ ]   [.mid を書き出す]   │
│  ┌───────────────────────────────────────┐  │
│  │  ░░▓▓░  ピアノロール（canvas）          │  │  ← ノートを矩形で

入力前は「投入口」が主役、採譜後は「プレイヤー＋ピアノロール」が主役、と画面の重心が切り替わる。

## 4. 内部のデータフロー（モジュール分割の素案）

```
入力層        AudioBuffer を作るだけ。経路を吸収する
  ├ fileInput      File → ArrayBuffer → decodeAudioData
  └ tabCapture     getDisplayMedia → MediaRecorder/録音 → decodeAudioData
        │
        ▼  AudioBuffer（モノラル/22050Hz は basic-pitch 側で処理）
採譜層  transcribe()  ← Web Worker に逃がす候補
        │            basic-pitch → frames/onsets/contours → Note[]
        ▼  Note[]（共通の中間表現）
        ├──────────────┬───────────────┐
        ▼              ▼               ▼
   描画 PianoRoll   再生 Synth      書き出し midiExport
   (canvas)       (sf2/spessa)     (@tonejs/midi)
```

### 設計の要: `Note[]` という共通の中間表現

真ん中の `Note[]`（音高・開始・終了・強さの配列）を**全モジュールの境界**にする。

```ts
type Note = {
  pitch: number;   // MIDI ノート番号 (0–127)
  start: number;   // 秒
  end: number;     // 秒
  velocity: number;// 0–1（強さ）
};
```

この境界を守ると各部分が**疎結合**になる:

- 入力経路（ファイル / タブ）が増えても、採譜から先は無変更。
- 表示・再生・書き出しは `Note[]` を読むだけの独立した 3 つの出口。
- 採譜エンジンを差し替えても出口は無変更。

React のコンポーネントもこの層に対応させる: `<Dropzone>` / `<TranscribeProgress>` / `<PianoRoll>` / `<Player>` / `<ExportButton>`。

## 6. 制約（必ず守る）

- **完全クライアント完結**。サーバを持たない。
- ゆえに **「URL 貼り付けで即ダウンロード」は実装しない**（yt-dlp 相当はブラウザでは不可）。
- 入力は「ファイル D&D」と「タブ音声キャプチャ」のみ。
- ライセンス 2 種に注意: 入力素材（改変 OK のものを）／同梱 sf2（再配布可のものを）。
